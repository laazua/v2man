## 2. 用户管理

入口：管理功能 → **「用户管理」**

### 功能列表

| 操作 | 说明 |
|------|------|
| **查看用户** | 列表展示用户名、邮箱、套餐、余额、流量、状态、到期日 |
| **编辑用户** | 修改套餐、流量配额、状态、邮箱、密码；修改后自动同步到节点 |
| **手动充值** | 直接为用户增加余额（不通过充值流程） |
| **重置订阅** | 更换用户 UUID，原订阅链接立即失效 |
| **同步配置** | 手动将用户配置推送到关联节点（SSH） |
| **筛选搜索** | 按状态、套餐筛选，按用户名/邮箱搜索 |

### 编辑用户字段说明

| 字段 | 说明 |
|------|------|
| **套餐** | 选择用户所属套餐，为空则无套餐限制 |
| **已用流量 (MB)** | 已使用的流量数值，可手动调整 |
| **总流量 (MB)** | 套餐流量上限，购买套餐时自动设置 |
| **是否活跃** | 控制用户能否连接节点 |
| **到期时间** | 套餐到期日期 |
| **邮箱** | 用户邮箱，用于密码重置 |
| **密码** | 留空不修改，填写则覆盖用户密码 |

> `traffic_used` 字段会与流量采集数据累加，手动修改后注意核对。

## 3. 节点管理

入口：管理功能 → **「节点管理」**

### 节点字段

| 字段 | 说明 |
|------|------|
| **名称** | 节点显示名称（对用户可见） |
| **协议** | V2Ray 传输协议 (vmess/vless/trojan) |
| **地址** | 节点服务器 IP 或域名 |
| **端口** | V2Ray 监听端口 |
| **是否活跃** | 控制节点是否出现在订阅列表中 |
| **排序** | 控制节点在用户端的显示顺序 |

### SSH 连接配置

部署和同步功能需要 SSH 连接节点。两种认证方式：

```yaml
# 方式1：密钥认证（推荐）
ssh_key: |
  -----BEGIN OPENSSH PRIVATE KEY-----
  ...
  -----END OPENSSH PRIVATE KEY-----
ssh_user: root
ssh_port: 22

# 方式2：密码认证
ssh_password: your-password
ssh_user: root
ssh_port: 22
```

### 部署节点

点击节点 **「部署」** 按钮，系统自动完成：

1. SSH 连接到节点服务器
2. 检测并安装 V2Ray 核心（如未安装）
3. 生成 V2Ray 配置文件（基于模板）
4. 配置 systemd 服务并启动
5. 同步所有活跃用户配置

部署过程中输出实时日志。部署失败可查看错误信息排查。

### 节点依赖

部署流程需要在目标节点上解压 V2Ray 安装包，因此目标节点必须安装 **unzip**：

```bash
# Debian / Ubuntu
apt install -y unzip

# CentOS / RHEL / Rocky / Alma
yum install -y unzip

# Fedora
dnf install -y unzip
```

> 如果节点上已安装 python3，系统会优先使用 python3 的 zipfile 标准库解压，不依赖 unzip。仅在 python3 不可用时才回退到 unzip。

### 节点同步

- **新增/编辑用户** → 自动触发节点同步
- **重置用户订阅** → 自动同步到节点
- **定时同步** → 每 15 分钟自动执行 `sync_users` 命令

## 4. 套餐管理

入口：管理功能 → **「套餐管理」**

### 套餐字段

| 字段 | 说明 |
|------|------|
| **名称** | 套餐显示名称（如"基础版"） |
| **价格 (分)** | 以分为单位的定价，100 分 = 1 元 |
| **流量 (GB)** | 套餐包含的总流量，以 GB 为单位 |
| **天数** | 套餐有效天数 |
| **是否上架** | 控制套餐是否对用户可见 |
| **排序** | 控制套餐在用户端的显示顺序 |
| **关联节点** | 选择该套餐可使用的节点（多选） |

### 注意事项

- 用户购买套餐后，`traffic_total` 和 `expire_date` 被更新
- 到期后系统自动清空流量并停用用户（由 `check_expired` 命令执行）
- 已上架的套餐无法删除，请先下架再操作

## 5. 充值审核

入口：管理功能 → **「充值审核」**

### 审核流程（手动模式）

```
用户提交充值申请 → 管理员查看 → 确认到账 → 余额自动增加
                                    → 拒绝（填写原因）
```

### 页面功能

| 操作 | 说明 |
|------|------|
| **筛选** | 按状态（待审核/已完成/已拒绝）切换 |
| **搜索** | 按用户名搜索充值记录 |
| **确认到账** | 标记充值完成，自动增加用户余额并处理邀请返利 |
| **拒绝** | 标记充值失败，填写拒绝原因 |

### Django Admin 批量操作

在 `/admin/` 中，支持选中多条充值记录，通过 **「确认选中的充值」** action 批量确认。

### 自动模式

当系统配置为 **自动到账模式** 时，用户支付成功后系统自动创建充值记录（状态为已完成），无需管理员审核。

## 6. 支付设置

入口：管理功能 → **「充值设置」**

### 充值模式切换

```
手动审核模式 ─── 用户提交 → 管理员确认到账
自动到账模式 ─── 用户支付 → 系统自动到账
```

### 支付驱动配置（自动模式）

| 驱动 | 说明 | 适用场景 |
|------|------|---------|
| **模拟驱动** | 开发测试用，模拟支付回调 | 开发环境 |
| **支付宝当面付** | 真实支付宝，生成动态二维码 | 生产环境 |

### 支付宝配置项

| 配置 | 说明 |
|------|------|
| **APPID** | 支付宝开放平台应用 ID |
| **应用私钥** | RSA2 私钥（PEM 格式） |
| **支付宝公钥** | 从支付宝开放平台获取的公钥（PEM 格式） |
| **通知地址** | 支付宝异步回调地址（只读，需在支付宝平台配置） |

详细对接步骤见 `docs/deployment/alipay-integration.md`。

### 收款码管理

入口：管理功能 → **「收款码管理」**

上传支付宝收款码图片（手动模式使用），支持 JPG/PNG/GIF 格式，大小不超过 2MB。

## 7. 邀请管理

入口：管理功能 → **「邀请管理」**

### 返现设置

| 设置项 | 说明 |
|--------|------|
| **返现比例** | 被邀请人充值时，邀请人获得的返利百分比（默认 20%） |

| 操作 | 说明 |
|------|------|
| **通过** | 提现申请通过，状态标记为"已通过" |
| **拒绝** | 拒绝提现，金额自动退回用户余额 |

## 9. 客服管理

入口：管理功能 → **「客服管理」**

用户通过 **「联系客服」** 提交的留言管理：

1. 查看用户的留言列表（主题、状态、时间）
2. 点击留言进入详情，查看完整对话
3. 输入回复内容，点击 **「发送」**
4. 用户侧会收到客服回复的通知提醒

功能特性：
- **未读计数**：导航栏上显示未回复的留言数量
- **回复可见性**：可设置回复对用户可见或隐藏

## 10. 调度任务

系统内置三个定时任务，由 `run_scheduler` 命令统一调度：

| 任务 | 周期 | 说明 |
|------|------|------|
| `collect_traffic` | 每 5 分钟 | SSH 到所有活跃节点，通过 V2Ray StatsService 采集流量 |
| `sync_users` | 每 15 分钟 | SSH 到所有活跃节点，同步用户 UUID 和配置 |
| `check_expired` | 每 6 小时 | 检查所有到期用户，自动停用并清空流量 |

### 启动调度器

```bash
# 开发环境（需要单独开一个终端）
cd app
uv run manage.py run_scheduler

# 生产环境（systemd 托管）
systemctl start v2man-scheduler
```

### 手动执行

```bash
# 手动采集流量
uv run manage.py collect_traffic

# 手动同步用户到指定节点
uv run manage.py sync_users --node 节点名称

# 手动检查到期用户
uv run manage.py check_expired
```

## 11. Django Admin

入口：`/admin/`（Django 原生管理后台，功能更全面）

### 注册的模型

| 模型 | 功能 |
|------|------|
| **User** | 用户列表（用户名、邮箱、套餐、流量、状态） |
| **Recharge** | 充值记录 + 批量确认 action |
| **Wallet** | 钱包余额查看 |
| **PaymentConfig** | 支付配置查看 |
| **Node** | 节点管理（名称、协议、地址、端口、SSH 配置） |
| **Subscription** | 用户订阅 Token 列表 |
| **Plan** | 套餐配置（名称、价格、流量、天数、关联节点） |
| **TrafficLog** | 流量日志查询 |
| **ContactMessage** | 客服留言查看 |
| **Notification** | 系统公告管理 |
| **InviteCode** | 邀请码管理 |
| **Referral** | 邀请关系查看 |
| **Withdrawal** | 提现申请 + 通过/拒绝 actions |
| **SystemSetting** | 系统配置 KV 表 |

### 常用操作

```python
# 批量确认充值
# 在 Recharge 列表页，勾选待审核记录，下拉选择「确认选中的充值」

# 批量处理提现
# 在 Withdrawal 列表页，勾选待审核记录，选择「通过选中的提现」或「拒绝选中的提现」
```

## 12. 运维命令

```bash
# ========== 部署相关 ==========
docker compose up -d                    # 启动所有服务
docker compose down                     # 停止所有服务
docker compose logs -f                  # 查看实时日志
docker compose logs -f cron             # 查看调度器日志
docker compose exec web uv run manage.py migrate  # 执行数据库迁移
docker compose exec web uv run manage.py createsuperuser  # 创建管理员

# ========== 数据库 ==========
docker compose exec db pg_dump -U v2man v2man > backup.sql  # 备份数据库
docker compose exec web uv run manage.py dbshell  # 进入数据库命令行

# ========== 故障排查 ==========
docker compose exec web uv run manage.py check  # Django 系统检查
docker compose exec web uv run python -c "from payment.drivers import get_payment_driver; d = get_payment_driver(); print(type(d).__name__)"  # 验证支付驱动
```
